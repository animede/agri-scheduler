# 実装計画

前提: [spec.md](./spec.md) の仕様に基づく。技術構成は Python(FastAPI)+SQLite+React(TS)+Anthropic Claude API。
各フェーズは独立して動作確認できる単位に分割し、フェーズ完了ごとに実際にブラウザで触れる状態を目指す。

## フェーズ0: プロジェクト基盤構築
- リポジトリ初期化（git init）、ディレクトリ構成決定（`backend/`, `frontend/`, `docs/`, `data/`）
- FastAPIプロジェクト雛形、SQLAlchemyセットアップ、SQLiteファイル配置
- Reactプロジェクト雛形（Vite + TypeScript）、開発用起動スクリプト（backend/frontendを同時起動）
- Anthropic APIキーの環境変数管理（`.env`、`.gitignore`整備）
- 成果物: `curl http://localhost:8000/health` と フロントの空ページが表示できる状態

## フェーズ1: コアデータモデル & CRUD API
- テーブル実装: Field, Bed, BedSegment, CropFamily, Crop, Variety, Planting, Task
- CropFamilyの初期マスタ投入（ナス科・ウリ科・アブラナ科・マメ科等の輪作年限）
- 各エンティティのCRUD APIエンドポイント（作成・一覧・詳細・更新・削除）
- 簡易な動作確認用のAPIドキュメント（FastAPI自動生成のSwagger UIで代替、専用UIはまだ不要）
- 成果物: Swagger UIから圃場・畝・区画・品種・作付けを一通り登録できる

## フェーズ2: 圃場マップ グラフィカルUI
- 圃場一覧・選択画面
- 圃場マップ画面（SVG）: 畝を矩形として配置、区画への分割操作、区画クリックで詳細パネル表示
- 畝・区画の追加/編集フォーム（数値入力：長さ・幅・向き・配置座標）
- 区画に現在の作付け（品種・生育ステージ）を色分け表示
- 成果物: ブラウザ上で畝レイアウトを作成し、区画をクリックして詳細が見られる

## フェーズ3: 品種マスタ管理UI（手動入力部分）
- 品種登録・編集フォーム（栽培暦、株間・条間、マルチング要否、保温対策メモ）
- 地域帯（寒地/温暖地/暖地）別の時期入力対応
- ユーザー設定（自分の気候帯）画面
- 品種一覧・検索
- 成果物: 手動入力のみで品種マスタが一通り作れる（AI解析はまだ無し）

## フェーズ4: 作付け登録 & 連作障害チェック
- 区画×品種×年で作付けを登録するフロー
- 区画の輪作履歴（過去作付けの科）をAPIで算出するロジック実装
- 登録時に輪作年限抵触チェック→警告UI表示（ブロックはしない）
- 圃場マップ上に輪作リスクアイコンを表示
- 成果物: 同じ区画に連続してナス科を作付けしようとすると警告が出る

## フェーズ5: 作業タスク自動生成 & 時期推測
- 品種の栽培暦から作業テンプレート（土作り→畝立て→種蒔き→育苗→マルチング/保温→植付→中間管理→収穫→片付け）を導出するロジック
- Planting登録時にTaskレコードを自動生成
- 実施日入力による後続タスクの推奨時期再計算ロジック
- タスク一覧・完了チェックUI（区画詳細パネルから）
- 成果物: 作付け登録すると自動でタスクリストが生成され、チェックできる

## フェーズ6: AI画像解析パイプライン
- 品種登録フォームに画像アップロードUIを追加
- バックエンド: 画像をAnthropic Claude Vision APIへ送信し、構造化スキーマ（種蒔き時期・育苗日数・植付時期・収穫時期・株間条間・マルチング推奨・保温対策等）で抽出するプロンプト実装
- 抽出結果を品種登録フォームに自動反映するUI（AI抽出値 vs 手動修正値を区別して保持）
- 元画像・AI生レスポンスの保存と再確認UI
- ネットワーク未接続時のフォールバック（手動入力への切替メッセージ）
- 成果物: 種袋画像をアップロードすると栽培暦フォームが自動入力され、確認・修正して保存できる

## フェーズ7: 栽培カレンダービュー（非ガントの年間ビュー）
- シーズンホイール or 横スクロールタイムラインのSVGコンポーネント設計・実装
- 作付けごとのステージバー（種蒔き→育苗→植付→管理→収穫）をアイコン付きで描画
- 圃場マップとカレンダービューの連動（区画選択→該当作付けにフォーカス）
- 今週の推奨作業のサマリ表示
- 成果物: 年間カレンダービューで全作付けの状況を一覧できる

## フェーズ8: 年間計画のロール（次年度展開）機能
- 年切り替えUI（前年/翌年ナビゲーション）
- 「次年度にロール」操作: 当年の区画レイアウトをベースに翌年計画のたたき台を生成
- 輪作ルールを踏まえた作物候補提示（同一区画で同一科を連続提案しない簡易ロジック）
- 過去年度データのアーカイブ表示（読み取り専用）
- 成果物: 年度をまたいでロールし、輪作を考慮したたたき台から翌年計画を組み立てられる

## フェーズ9: 仕上げ・運用整備
- データバックアップ手順（SQLiteファイルコピー）のドキュメント化
- 起動スクリプト・READMEの整備（個人利用前提のセットアップ手順）
- 全体UI/UXの調整（配色、レスポンシブ、タブレット幅での見え方）
- 一通りのシナリオ通し確認（品種登録→作付け→タスク管理→カレンダー確認→次年度ロール）

## 依存関係・進め方の補足
- フェーズ0〜1は前提基盤のため必須先行。
- フェーズ2（圃場マップ）とフェーズ3（品種マスタ手動入力）は並行実装可能。
- フェーズ6（AI画像解析）はフェーズ3の品種登録フォームに依存するため、フェーズ3完了後に着手。
- フェーズ7（カレンダービュー）はフェーズ5（タスク自動生成）のデータ構造に依存。
- フェーズ8（年間ロール）は連作チェック（フェーズ4）とカレンダービュー（フェーズ7）の両方に依存するため最後の主要機能として実装。
- 各フェーズ完了時にブラウザで実際に操作し、動作確認してから次フェーズに進む。
