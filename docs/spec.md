# 農場作付け管理システム 仕様書

## 1. 目的・背景

小規模畑作農家（個人利用）向けに、多品種の作付け計画を視覚的に管理するシステムを構築する。
既存のガントチャート型スケジュール管理ではなく、畑の物理レイアウトと栽培工程を直感的に把握できる
グラフィカルUIを提供する。種苗会社が配布する作付け説明画像（種袋の裏面など）をAI画像解析で読み取り、
栽培スケジュール（種蒔き・育苗・植え付け・収穫の時期）を自動的に構造化データへ変換することで、
入力の手間を大幅に削減する。

## 2. 利用条件（前提）

| 項目 | 内容 |
|---|---|
| 利用形態 | Webアプリ（ローカルPC/サーバーで稼働、ブラウザからアクセス） |
| 利用者 | 個人（自分のみ）。ログイン機構は不要 |
| ネットワーク | 基本オフライン運用。AI画像解析の実行時のみインターネット接続が必要 |
| 対象作型 | 露地・畑作の畝栽培（水田は対象外） |
| 対応言語 | 日本語UI |

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| 圃場（ほじょう） | 管理対象の畑全体。複数登録可能 |
| 畝（うね） | 圃場内の物理的な栽培列。長さ・向き・幅を持つ |
| 区画（くかく） | 畝を分割した単位。1畝に複数品種を植える場合に使用 |
| 作物（さくもつ） | トマト、キャベツなど大分類。連作障害判定の基準となる「科」を持つ |
| 品種（ひんしゅ） | 作物の具体的な品種名（例：桃太郎、アイコ）。栽培暦（時期・株間等）を持つマスタ |
| 作付け（さくづけ） | ある区画に、ある品種を、ある年・作期で植える計画・実績の1レコード |
| 輪作年限 | 同じ科の作物を再度作付けするまでに空けるべき年数 |
| 作業（さぎょう） | 種蒔き・間引き・マルチング・誘引・追肥・収穫など、作付けに紐づく個別のタスク |

## 4. 機能要件

### 4.1 圃場・畝・区画管理
- 圃場を複数登録できる（名称、場所メモ、面積）。
- 圃場内に畝を登録できる（畝番号/名称、長さ(m)、幅(cm)、向き、圃場内での配置座標）。
- 畝は分割して複数の区画を作れる（区画ごとに長さ比率または実長を指定）。
- 圃場マップ上で畝・区画を矩形として視覚的に配置・編集できる（ドラッグ操作 or 数値入力）。
- 各区画には現在の作付け状況（品種・生育ステージ）が色分けで表示される。

### 4.2 作物・品種マスタ管理
- 作物（大分類）は「科」を必須で持つ（連作障害判定用）。科ごとの標準輪作年限をマスタとして保持し、編集可能にする。
  - 初期マスタ例：ナス科(3–4年)、ウリ科(2–3年)、アブラナ科(1–2年)、マメ科(2–3年)、セリ科(1–2年)、キク科(1–2年)、ヒガンバナ科/ネギ科(1年)、ヒユ科(1年) 等
- 品種は以下の項目を持つ：
  - 品種名（自由入力）、紐づく作物（科）
  - 栽培暦：種蒔き時期（範囲）、育苗日数、植え付け時期（範囲）、収穫時期（範囲）、生育日数目安
  - 地域帯別の時期差（寒地・温暖地・暖地）※種袋の記載形式に対応
  - 株間・条間（cm）
  - マルチング要否・種類（黒マルチ／シルバーマルチ／無し等）
  - 保温・保湿対策メモ（トンネル、べたがけ等）
  - 参考画像（種袋・作付け説明画像）の添付
  - AI解析による自動抽出結果と、ユーザーによる手動修正値（両方保持し、手動修正を優先）
- ユーザーの地域（気候帯：寒地/温暖地/暖地）を設定でき、時期表示・作業推測に反映する。

### 4.3 種苗会社画像のAI解析（自動抽出）
- 品種登録時に、種苗会社の作付け説明画像（例：種袋裏面の栽培歴表・イラスト）をアップロードできる。
- アップロード画像をAI（Claude Vision）に渡し、以下を構造化データとして自動抽出する：
  - 種蒔き時期、育苗期間、植え付け時期、収穫時期（地域帯別に分かれている場合はそれぞれ）
  - 株間・条間、マルチング推奨、保温対策の要否、日照条件、その他の栽培上の注意点
- 抽出結果は品種登録フォームに自動反映されるが、確定前に必ずユーザーが確認・修正できる（AIの誤読を前提とした確認ステップを必須にする）。
- 解析元画像とAIの生レスポンス（抽出根拠）を保存し、後から再確認できるようにする。

### 4.4 作付け計画（区画×品種×年）
- 区画に対し、年・品種を指定して作付け計画を作成する。
- 作成時に、その区画の過去の作付け履歴（科）を参照し、輪作年限に抵触する場合は警告を表示する（強制ブロックはせず、警告＋理由表示のうえユーザーが判断）。
- 作付けごとに、品種の栽培暦から作業タスクを自動生成する：
  - 土作り（堆肥・元肥投入）→ 畝立て → （育苗が必要な品種は）種蒔き→育苗管理 → マルチング/保温対策 → 植え付け → 誘引・整枝・追肥（中間管理） → 収穫 → 片付け・残渣処理
  - 各タスクは「推奨時期（範囲）」を持ち、実際の実施日・完了チェックを記録できる。
- 計画（予定日）と実績（実施日）を分けて保持し、ズレを可視化する。

### 4.5 連作障害チェック
- 区画ごとに作付け履歴（年×科）を保持する。
- 新規作付け登録時、当該区画で過去N年以内に同一科（または相性の悪い組み合わせ）が作付けされていないかを判定し、警告バッジ・理由（例：「ナス科は4年空ける必要がありますが、2年前にナスを栽培しています」）を表示する。
- 圃場マップ上でも、輪作リスクのある区画をアイコン表示する。

### 4.6 グラフィカルUI（ガントチャート代替）
- **圃場マップビュー**：畝・区画を実際のレイアウトに近い形で表示し、品種ごとに色分け。クリックで区画詳細（現在の作付け・生育ステージ・次の作業）をカード表示。
- **栽培カレンダービュー**：1年間（1〜12月）を円環（シーズンホイール）または横スクロール型のビジュアルタイムラインで表現し、各作付けを「種蒔き→育苗→植付→管理→収穫」のアイコン付きステージバーとして表示する。表形式のガントチャートは採用しない。
- 両ビューは連動し、圃場マップで区画を選ぶとカレンダービューが該当作付けにフォーカスする。

### 4.7 年間計画のロール（次年度展開）
- 年間計画を年単位でスクロール/切り替えできるUI（前年・翌年へ移動）。
- 「次年度にロール」操作で、当年の作付け構成（区画レイアウト）をベースに翌年計画のたたき台を作成できる。
  - このとき同一区画に同一科を連続提案しないよう、輪作ルールを踏まえた作物候補の提示（自動で科をずらす簡易提案、最終判断はユーザー）を行う。
- 過去年度の実績はアーカイブとして保持し、輪作履歴・見返しに利用する。

### 4.8 作業と時期の推測
- 品種の栽培暦・ユーザーの気候帯・植え付け日（実績）から、以降の作業（マルチング撤去、誘引、追肥、収穫開始）の推奨時期を自動計算し、タスクとして提示する。
- 実際の植え付け日が計画からずれた場合、後続タスクの推奨時期を実績基準で再計算する。

## 5. 非機能要件
- 個人利用のためログイン・権限管理は実装しない（ローカルネットワーク内での利用を前提）。
- データはローカルにファイルベース（SQLite）で永続化し、バックアップ（DBファイルのコピー）で復旧可能とする。
- AI画像解析はネットワーク接続時のみ利用可能な機能とし、オフライン時は手動入力にフォールバックできる。
- レスポンシブ対応（PC操作を主としつつ、畑での確認用にタブレット幅でも閲覧可能）。

## 6. 対象外（今回のスコープ外）
- 複数ユーザーでの同時編集・権限管理
- 水田・果樹園など畝栽培以外の作型
- 気象データ連携（将来拡張候補）
- 販売・会計管理機能

## 7. 推奨技術構成

| レイヤ | 技術 | 理由 |
|---|---|---|
| バックエンド | Python 3.12 + FastAPI + SQLAlchemy | AI連携（Anthropic SDK）とデータ処理の親和性が高く、個人開発でも保守しやすい |
| DB | SQLite | ローカル運用・個人利用に十分。ファイル1つでバックアップ容易 |
| フロントエンド | React + TypeScript + Vite | 圃場マップ・カレンダーホイールなどカスタムグラフィカルUIをSVG/Canvasで自由に実装可能 |
| グラフィカルUI描画 | SVG（react + 独自コンポーネント） | ガントチャート専用ライブラリを使わず、畝レイアウト・シーズンホイールを自由にデザイン |
| AI画像解析 | Anthropic Claude API（Vision, claude-sonnet-5） | 種袋画像から栽培暦を構造化抽出。日本語画像の読み取り精度と構造化出力の指示追従性が高い |
| 画像保存 | ローカルファイルシステム（`data/images/`）+ DBにパス保存 | 個人利用でクラウド不要 |
| 起動方法 | `uvicorn`（API）+ Viteビルド成果物を静的配信 | 単一プロセスでの起動を想定し、運用を簡素化 |

## 8. データモデル概要（ER概要）

```
Field(圃場) 1---* Bed(畝) 1---* BedSegment(区画)
CropFamily(科マスタ: 輪作年限) 1---* Crop(作物)
Crop 1---* Variety(品種) *---1 SourceImage(参考画像/AI抽出結果)
BedSegment 1---* Planting(作付け: 区画×品種×年) *---1 Variety
Planting 1---* Task(作業: 種類/推奨時期/実施日/完了フラグ)
BedSegment 1---* RotationHistory(輪作履歴: 年×科) ※Plantingから導出可
```

## 9. 主要ユースケース（シナリオ）

1. **品種登録**：種苗会社の種袋を撮影 → アップロード → AIが栽培暦を抽出 → ユーザーが確認・修正 → 品種マスタに保存。
2. **作付け計画**：圃場マップで区画を選択 → 品種を選んで作付け登録 → 輪作警告があれば確認 → 作業タスクが自動生成される。
3. **日々の管理**：カレンダービューで今週の推奨作業（マルチング・誘引・追肥等）を確認 → 実施したらチェック → 後続タスクの時期が自動調整。
4. **年度更新**：シーズン終了後、「次年度へロール」→ 前年構成をベースに翌年のたたき台を作成 → 輪作を考慮した作物候補を見ながら再配置。
